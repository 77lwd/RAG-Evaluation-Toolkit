# Install the Toolkit and Skill

## Install from a checkout

Clone the Toolkit repository, create a virtual environment, and install the package in editable
mode. This installs the `rag-evaluation` command and keeps dependencies isolated from the host
project:

```powershell
git clone https://github.com/77lwd/RAG-Evaluation-Toolkit.git
cd RAG-Evaluation-Toolkit
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
rag-evaluation --help
python -m examples.quickstart
python -m unittest discover -s tests -p 'test_rag_evaluation_*.py' -v
```

Use `source .venv/bin/activate` to activate the environment on macOS/Linux. The package supports
Python 3.10 or newer. `requirements-evaluation.txt` remains available for a fully pinned test
environment.

The quickstart uses temporary synthetic evidence, runs no model, and deletes its temporary
registry when it exits. Its `complete_for_independent_review` and `valid_metadata_seal` results
demonstrate metadata workflow only; they are not evidence of real organizational readiness.

## Codex Skill

The Codex Skill is the `skills/rag-evaluation` folder. To make it available in this checkout,
copy it into the project-scoped Agent Skills directory:

```powershell
New-Item -ItemType Directory -Force .agents/skills/rag-evaluation | Out-Null
Copy-Item skills/rag-evaluation/* .agents/skills/rag-evaluation/ -Force
```

For a user-level installation shared across projects, copy the same folder to
`$HOME/.agents/skills/rag-evaluation`. Keep the toolkit checkout available as the working
directory when using the Skill, because its workflow references the checkout's `examples/` files
and Python module.

Review the Skill instructions before using them with a team's data. The Skill guides the
workflow; the Toolkit performs schema, registry, and evidence-reference checks. Neither
authenticates people, establishes legal permission, proves real access controls, or authorizes a
model run.

## Team trial from a configured comparison

Start from `examples/inventory-config.example.json`. Replace all example system IDs, identities,
source roots, paths, and allowlists with team-owned values. Keep the generated inventory directory
outside every configured source root. The `comparison` section can contain one baseline and two or
more candidates.

From the Toolkit checkout root, install dependencies and run the configured workflow:

```powershell
python -m pip install -r requirements-evaluation.txt
python -m rag_evaluation inventory-configured --config <team-config.json> --output <inventory-output>
python -m rag_evaluation init --registry <registry-path>
python -m rag_evaluation register-comparison-bundle --registry <registry-path> --bundle <inventory-output> --reference-output <plan-ref.json>
python -m rag_evaluation review-comparison --registry <registry-path> --reference <plan-ref.json>
python -m rag_evaluation draft-readiness --registry <registry-path> --reference <plan-ref.json> --readiness-id <readiness-id> --output <readiness-draft.json> --unit-id <opaque-unit-id>
```

Repeat `--unit-id` for each opaque review unit. The readiness draft includes two reviewer slots for
every arm/unit pair. Replace all `TODO` people and reviewer IDs with distinct, accountable human
participants; replace every evidence placeholder with a real artifact reference generated by
`fingerprint`. Then register the completed file and write its exact reference:

```powershell
python -m rag_evaluation register --registry <registry-path> --document <completed-readiness.json> --reference-output <readiness-ref.json>
python -m rag_evaluation review-readiness --registry <registry-path> --reference <readiness-ref.json> --root <evidence-root-id>=<evidence-root-path>
```

Use one `--root ID=PATH` option for each evidence root. A blocked report is a request for the team
to resolve missing controls, not a waiver opportunity. `complete_for_independent_review` still
does not authenticate people or evidence, establish formal readiness, or authorize a run. The
source checkout can be installed and used, but the project does not yet publish PyPI packages,
tagged releases, or an upgrade/migration lifecycle.

## Other hosts

This folder follows the Agent Skills directory format (`SKILL.md` plus optional resources), but
host discovery paths and installation procedures differ. Copy or package the Skill for the
target host according to that host's current documentation. Responses API hosted Skills are a
separate, versioned upload workflow; this repository does not upload or publish a hosted Skill.

## Team distribution

Share a reviewed, versioned source release of the whole toolkit checkout. Keep the Skill and
Toolkit together so examples and CLI instructions remain aligned. Do not distribute real
evidence in the repository; teams should keep evidence in their approved storage and pass only
the necessary local root bindings to review commands.
